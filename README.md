# llm_check_bot

Telegram-бот для группового чата. Он:

- 🤖 **ловит нейрослоп** — сообщения, сгенерированные нейросетью и вставленные в чат почти без правок, — и отвечает стикером и «🚨 Нейрослоп детектед 🚨»;
- 💙 **замечает сообщения о суицидальных мыслях** и отвечает поддержкой с телефонами помощи;
- 💘 **ведёт счётчик любовников** — кто кого и сколько раз упоминал по имени в любовном контексте или как время вместе (`/men` — рейтинг).

Все проверки делает локальная модель **[Gemma 4 E2B](https://ollama.com/library/gemma4) (`gemma4:e2b-mlx`)** через [Ollama](https://ollama.com) прямо на вашем Mac: без платных API, сообщения из чата никуда не уходят.

## Архитектура

```
┌──────────────── Telegram ────────────────┐
│  группа  ──сообщения──▶  бот  ──ответы──▶ │
└──────────────────────────┬───────────────┘
                           │ long polling
┌─────────── Docker ───────┼───────────────────────────────┐
│                          ▼                               │
│  bot (Go) ── фильтры ──▶ очередь к модели ──┐            │
│      │                  (1 запрос за раз,   │            │
│      │                   пауза LLM_MAX_LOAD)│            │
│      ▼                                      │            │
│  redis: история стиля, счётчик любовников,  │            │
│         отметки «уже ответил», кулдауны     │            │
└─────────────────────────────────────────────┼────────────┘
                                              │ host.docker.internal:11434
┌──────────── Mac (без Docker) ───────────────▼────────────┐
│  Ollama + gemma4:e2b-mlx  ← видеочип Apple (MLX)         │
└──────────────────────────────────────────────────────────┘
```

**Почему Ollama не в Docker.** На macOS контейнеры работают в виртуальной машине Linux без доступа к видеочипу Apple: модель там считалась бы только на процессоре — в разы медленнее и горячее, а MLX-модели не запустились бы вовсе. Поэтому Ollama работает на самом Mac, а бот в контейнере обращается к ней по сети.

**Как обрабатывается сообщение:**

1. **Быстрые проверки без модели.** Боты, сообщения от имени канала, пересылки и команды пропускаются. Явные фразы о суициде («я у с», «не хочу жить»…) ловятся регулярным выражением сразу — ответ поддержкой.
2. **Решение, нужна ли модель.** Длинное сообщение отслеживаемого пользователя проверяется на слоп; короткие запоминаются как образец его стиля. Для счётчика любовников фильтр пропускает только сообщения с «любовными» словами или словами про время вместе рядом с именем.
3. **Один запрос к модели на сообщение.** Если нужны и слоп, и счётчик, модель отвечает на всё сразу: оценка слопа, риск суицидальных мыслей, список названных людей с контекстом. Если нужен только счётчик — короткий отдельный запрос.
4. **Решение в коде, не в модели.** Модель только классифицирует (контекст «love / together / work / chores / family / other»), а засчитывает код: только love и together, без родственников и слов вроде «бывший» вместо имени.
5. **Ответ** в чат и запись в Redis.

**Структура кода:**

| Пакет | Что делает |
|---|---|
| `main.go` | приём сообщений из Telegram, логика обработки, очередь и ограничитель нагрузки, ответы |
| `internal/detector` | промпты и запросы к модели (Ollama или Claude), фильтры слов, разбор и починка JSON |
| `internal/history` | история стиля, отметки «уже ответил», кулдауны — в памяти или в Redis |
| `internal/mencount` | счётчик любовников — в JSON-файле или в Redis |
| `internal/config` | настройки из `.env` и окружения |
| `redact.go` | вырезает токен Telegram из сетевых ошибок, чтобы он не попал в логи |

## Запуск

### 1. Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. **Отключите privacy mode**: `/setprivacy` → выберите бота → `Disable`. Иначе бот не увидит обычные сообщения в группе. Если бот уже был в группе — удалите и добавьте заново.
3. Добавьте бота в группу.

### 2. Модель (на Mac, без Docker)

```bash
brew install ollama
nice -n 10 taskpolicy -c utility ollama serve   # в отдельном терминале, с пониженным приоритетом
ollama pull gemma4:e2b-mlx                       # ~7,5 ГБ
```

### 3. Настройки

```bash
cp .env.example .env    # впишите TELEGRAM_BOT_TOKEN
```

`.env` в `.gitignore` и не попадёт в репозиторий.

### 4а. Запуск в Docker (бот + Redis)

```bash
docker compose up -d --build
docker compose logs -f bot
```

Данные Redis лежат в томе `redis-data` и переживают перезапуск. Остановить: `docker compose down` (данные сохранятся), `docker compose down -v` — вместе с данными.

### 4б. Запуск без Docker

```bash
go run .
```

Без `REDIS_URL` бот хранит историю в памяти, а счётчик любовников — в `data/men_counter.json`. С Redis: `REDIS_URL=redis://localhost:6379/0 go run .`

Узнать свой Telegram ID: напишите боту `/start` в личку.

## Функции

### 🤖 Нейрослоп

Модель оценивает сообщение по шкале 0–100 и объясняет оценку. С порога `SLOP_THRESHOLD` бот отвечает стикером и:

```
🚨 Нейрослоп детектед 🚨
Оценка: 90%
<объяснение модели>
```

Бот помнит обычные сообщения каждого пользователя (отдельно по чатам) и передаёт их модели как образец стиля: резкая смена манеры письма — сильный сигнал. В образец попадают только короткие сообщения и сообщения с явно низким баллом. Если сообщение отредактировали, бот проверит его заново, но второй раз не ответит.

> С размышлениями (`OLLAMA_THINK=on`) `gemma4:e2b-mlx` ставит живым сообщениям 0–30, а явному слопу — 95, поэтому порог по умолчанию 70. Без размышлений маленькая модель иногда завышает оценку живым сообщениям до 80–85 — тогда поднимите порог до 90.

### 💙 Поддержка при мыслях о суициде

Отдельно от слопа бот замечает сообщения о суицидальных мыслях и отвечает стикером и текстом поддержки с телефонами помощи (без оценки слопа):

- явные фразы («я у с», «убью себя», «не хочу жить», «покончить с собой» и т. п.) ловятся сразу, у всех участников и в сообщениях любой длины;
- в длинных сообщениях модель оценивает риск по намёкам («раздала вещи, дальше без меня»); шутки вроде «убейте меня, понедельник» не считаются;
- одному человеку в чате — не чаще раза в час.

Телефоны — российские: 8-800-2000-122 (телефон доверия), 8-495-989-50-50 (экстренная психологическая помощь МЧС), 112.

### 💘 Счётчик любовников

Включается флагом `LOVE_COUNTER` (по умолчанию `on`; `off` — выключить вместе с командой `/men`).

Бот считает, кто в чате кого и сколько раз упоминал **по имени**:

- **в любовном контексте** — влюблённость, краш, свидания, флирт, ревность, тоска по человеку: «влюбилась в Диму», «зову Машу на свидание», «кажется я запала на Олега», «Костя ❤️»;
- **как время вместе** — «мы с Димой идём в кино», «лежим с Сашей, смотрим сериал», «Петя позвал гулять».

Правило одинаковое для мужчин и женщин. Не считаются: без имени («бывший написал», «моя девушка ревнует»), работа и учёба («созвон с Олегом»), быт («Дима починил кран»), родственники («с братом Ваней»).

Счёт ведётся по каждому названному человеку отдельно, имена приводятся к именительному падежу («Диму», «Диме», «Дима» — один человек). При каждом засчитанном упоминании бот отвечает:

```
💘 Упоминание засчитано!
👨 Дима — 3 раза

Всего у Анастасии: 👨 4 · 👩 1
Рейтинг чата: /men
```

`/men` — рейтинг чата: у каждого участника всего 👨/👩 и самые упоминаемые имена. Пересланные и отредактированные сообщения не учитываются.

## Нагрузка на компьютер

Локальная модель нагружает видеочип и процессор, поэтому бот её бережёт:

- **один запрос к модели на сообщение** — слоп, риск и счётчик объединены;
- **узкий фильтр** — к модели идут только подходящие сообщения;
- **очередь** — `MAX_CONCURRENT_CHECKS=1`, и Ollama запускается с `OLLAMA_NUM_PARALLEL=1`: модель всегда обрабатывает один запрос, следующий ждёт;
- **ограничитель** — `LLM_MAX_LOAD=50`: после 3-секундной проверки 3 секунды паузы, модель занята не больше половины времени;
- **потоки** — `OLLAMA_NUM_THREAD=4`;
- **размышления** — `OLLAMA_THINK=on` делает проверку точнее, но дольше; если компьютер греется, а точность не так важна, поставьте `off`;
- **выгрузка из памяти** — через `OLLAMA_KEEP_ALIVE=2m` простоя модель освобождает память;
- **приоритет** — `nice -n 10 taskpolicy -c utility ollama serve`.

Если компьютер всё равно греется — уменьшите `LLM_MAX_LOAD` до 30 или возьмите модель ещё меньше.

MLX-модели в Ollama не поддерживают строгий формат ответа (structured output), поэтому бот передаёт пример JSON в промпте, вырезает JSON из ответа и чинит типичные ошибки маленьких моделей (лишние кавычки, слова вроде «Бывший» вместо имени). Для моделей со строгим форматом это происходит автоматически.

## Настройки

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `OLLAMA_URL` | `http://localhost:11434` | адрес Ollama (в Docker — `http://host.docker.internal:11434`, задано в compose) |
| `OLLAMA_MODEL` | `gemma4:e2b-mlx` | модель в Ollama |
| `OLLAMA_KEEP_ALIVE` | `2m` | через сколько простоя выгружать модель из памяти |
| `OLLAMA_NUM_THREAD` | `4` | сколько потоков процессора может занять модель (0 — все) |
| `OLLAMA_THINK` | `on` | модель рассуждает перед ответом: заметно точнее (на тестах 7/7 и 12/12 против 5/7 и 9/12), но 7–11 с на проверку вместо 1–2; `off` — быстрее и легче |
| `MAX_CONCURRENT_CHECKS` | `1` | сколько запросов к модели может идти одновременно |
| `LLM_MAX_LOAD` | `50` | какую долю времени (%) модель может работать; остальное — пауза между проверками |
| `WATCHED_USERS` | все | кого проверять на слоп: пусто или `*` — всех; иначе ID и/или @username через запятую |
| `SLOP_THRESHOLD` | `70` | порог 0–100, с которого бот отвечает на нейрослоп |
| `MIN_MESSAGE_LENGTH` | `30` | более короткие сообщения не проверяются на слоп |
| `SELF_HARM_THRESHOLD` | `60` | порог 0–100 риска суицидальных мыслей для ответа поддержкой |
| `STYLE_HISTORY` | `20` | сколько сообщений пользователя помнить как образец стиля (0 — выключить) |
| `LOVE_COUNTER` | `on` | счётчик любовников и команда `/men`: `on` / `off` |
| `SLOP_IMAGE` | `assets/sticker.webp` | картинка для ответов: `.webp` — стикером, `.png`/`.jpg` — фото; нет файла — текст |
| `REDIS_URL` | — | Redis для хранения данных (в Docker задано в compose); пусто — память + файл |
| `MEN_COUNTER_FILE` | `data/men_counter.json` | файл счётчика любовников без Redis |
| `DEBUG` | — | любое значение — писать в лог каждое сообщение (без текста) и причину пропуска |

## Безопасность

- Текст сообщений экранируется перед отправкой в модель, а из объяснений бота вырезаются ссылки и @упоминания — через сообщение нельзя «уговорить» модель или заставить бота написать что-то от своего имени.
- Токен Telegram вырезается из сетевых ошибок и не попадает в логи.
- `.env` не попадает ни в git, ни в Docker-образ.

## Облачная модель (необязательно)

Вместо локальной модели бот умеет работать через API Claude: `LLM_PROVIDER=claude`, `ANTHROPIC_API_KEY=...`, модель — в `CLAUDE_MODEL`. API оплачивается отдельно от подписки Claude, поэтому по умолчанию используется Ollama.
